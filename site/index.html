What the search saw
Moves

Twelve animals queue for the bar

You play one animal to the back of the queue and it acts. When five are queued, the front two get in and the last one is out. Points in the bar win.

Each generation beats the one before

Then match scores stop moving, and exploitability keeps falling

An exact best response copies the player until that ply, then plays perfectly. Its score above 50% is the number: how much the strongest possible opponent could win back. It is a lower bound on the whole game; plies 0 to 7 are not measured yet.

Four ways of deciding, by how much is still hidden

The only secret is each player's hand: four of the animals they have not played yet. The bars count the hands the opponent could be holding. As they shrink, the player switches from a learned network to exact solving.

What the measurements said

Every number is a line in runs/results.jsonl with its command, commit, seeds and 95% interval.

Run it

The engine, the search players and this site need no network weights. The re-solving player needs its two networks, which are not in the repository.

git clone https://github.com/diegooprime/beastybar-ai && cd beastybar-ai
python -m venv .venv && .venv/bin/pip install maturin numpy pytest
VIRTUAL_ENV=$PWD/.venv .venv/bin/maturin develop --release   # build the Rust engine
.venv/bin/python -m bbar.golden --engine core                 # rules check: 2000/2000 exact
.venv/bin/python -m bbar.arena pimc:w=128,d=8 greedy --deals 1000
python3 -m http.server -d site 8000                           # this page, with the engine in WebAssembly
Unofficial fan project. Beasty Bar is a game by Stefan Kloß, published by Zoch Verlag: buy it, it is very good. The animal drawings here are original. Scoring is a house rule: points in the bar, not animals.
